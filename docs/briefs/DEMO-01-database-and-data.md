# DEMO-01 — Demo database, minimal Presto, 1M-row synthetic data (Cursor agent A)

Read `docs/briefs/DEMO-00-contract.md` first, and `CLAUDE.md`. The contract is binding.

## Deliverables (all under `docker/demo/`)

1. **`docker-compose.yml`** — adds only a minimal **Presto 0.297** service (reuse
   `docker/presto/jvm.config` approach). It must reach the **existing** `postgres`
   container (host port 5433; same compose project/network as the root `docker-compose.yml`,
   or `host.docker.internal` — pick the one that works and document it). Do **not** start
   hive/minio/metastore/iceberg. One catalog only: `presto-catalog/demo_pg.properties`
   (`connector.name=postgresql`, `connection-url=.../analytics_demo`, user `demo_ro`).
   Raise Presto's own limits so a long fuzzy query isn't killed engine-side:
   `query.max-run-time` / `query.client.timeout` to >= 30m (config.properties).
   Size the JVM heap for 1M x 700k fuzzy join on a laptop; state the minimum RAM.
2. **`init-db.sh`** (idempotent, runnable against the live container, because the
   `postgresdata` volume already exists so `docker-entrypoint-initdb.d` will NOT run):
   create database `analytics_demo`, schema `demo`, role `demo_ro` (SELECT only).
   Safe to re-run; `--reset` drops and recreates `analytics_demo` ONLY (never `srse`).
3. **`seed.sql` / `seed.sh`** — deterministic, **set-based** (`generate_series`, `INSERT ...
   SELECT`), no row-by-row client inserts. `ROWS` env (default 1,000,000; `ROWS=20000`
   for M1) scales every table proportionally. Implements the distributions in the contract,
   fake IDs only. Ends with indexes + `ANALYZE`. Must finish for 1M in a few minutes.
4. **`docs/demo/DATA_PROFILE.md`** — generated by a `profile.sql` you also commit:
   row counts; bank/pension/ration overlap % with beneficiary; income/status mismatch %;
   rows per district/taluka/department; **name-block-size distribution** (count of
   `substr(lower(full_name),1,3)` blocks, max/p99/median block size); orphan %; duplicate %.
5. **Fuzzy benchmark** inside the profile: the fuzzy beneficiary-vs-bank query run
   **directly in Presto** (CLI/JDBC) unscoped and scoped to one district. Record wall time
   and the fan-out estimate the product's guard would compute
   (`sourceRows x targetRows / prod(max distinct)` on the blocking key; the limit is
   `SRSE_ANALYSIS_MAX_ESTIMATED_ROWS`, 50,000,000). If the unscoped estimate exceeds the
   guard, **tune the name distribution** (more long tail / more distinct) — do not raise the guard.
   Report the final numbers; if the fuzzy query cannot finish in 20 min, say so plainly.

## Acceptance

- `docker compose -f docker/demo/docker-compose.yml up -d` + `init-db.sh` + `seed.sh`
  from a clean checkout produces the contract tables; counts match the contract within 1%.
- `srse` database untouched (verify no new objects in it).
- Presto answers `SELECT count(*) FROM demo_pg.demo.beneficiary` and `SHOW CATALOGS`
  lists only `demo_pg` (+ system).
- Re-running seed yields identical data (compare a checksum of each table).
